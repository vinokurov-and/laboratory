# Лабораторная работа №2: "Обработка и оптимизация изображений с Webpack"

---

### **Цель работы**:

Изучить механизмы работы с загрузчиками (loaders) и модулями ресурсов (asset modules) для обработки изображений в проекте, используя Webpack.

---

### **Теоретическая часть**:

#### **1. Зачем обрабатывать изображения в Webpack?**

Веб-приложения часто используют изображения, и эффективная оптимизация может существенно уменьшить размер бандла и улучшить производительность приложения. Используя Webpack, можно автоматизировать процессы, такие как сжатие изображений, преобразование в разные форматы и встраивание их как Data URIs.

#### **2. Asset Modules в Webpack 5**

Начиная с Webpack 5, для работы с файлами (изображения, шрифты и т.д.) используются встроенные **Asset Modules**, которые заменяют устаревшие загрузчики `file-loader` и `url-loader`. Существует четыре типа asset modules:

- **`asset/resource`** — создаёт отдельный файл и экспортирует URL (аналог `file-loader`).
- **`asset/inline`** — экспортирует ресурс как Data URI (аналог `url-loader`).
- **`asset`** — автоматически выбирает между `resource` и `inline` в зависимости от размера файла.
- **`asset/source`** — экспортирует исходный код файла.

### **Практическая часть**:

#### **1. Настройка Webpack для обработки изображений**:

Добавьте правило для обработки изображений в ваш конфигурационный файл Webpack (`webpack.config.js`):

```javascript
const path = require('path');

module.exports = {
    entry: './src/index.js',
    output: {
        filename: 'bundle.js',
        path: path.resolve(__dirname, 'dist'),
        clean: true, // Очищает папку dist перед каждой сборкой
    },
    module: {
        rules: [
            {
                test: /\.(png|jpe?g|gif|svg)$/i,
                type: 'asset', // Автоматически выбирает между resource и inline
                parser: {
                    dataUrlCondition: {
                        maxSize: 8 * 1024 // Файлы меньше 8кб будут встроены как Data URI
                    }
                }
            },
        ]
    }
};
```

#### **2. Использование изображения в проекте**:

Добавьте изображение в папку `src/assets/` вашего проекта, импортируйте его и отобразите через `index.js` на HTML-странице.

```javascript
// src/index.js

// Импортируем изображение
import myImage from './assets/picture.jpg';

console.log("Привет, Webpack!");

// Создаём новый элемент <img> для отображения изображения
const imageElement = document.createElement('img');

// Устанавливаем путь к изображению для элемента <img>
imageElement.setAttribute('src', myImage);

// Получаем ссылку на элемент <body> в документе
const bodyElement = document.getElementsByTagName('body')[0];

// Добавляем созданный элемент <img> в элемент <body>
bodyElement.appendChild(imageElement);
```

В этом примере мы создаём новый элемент `<img>` и добавляем его в `<body>` нашего документа.

В итоге должна получиться примерно следующая структура проекта:

```
my-webpack-project/
├── dist/
│   ├── bundle.js
│   └── index.html
├── src/
│   ├── assets/
│   │   └── picture.jpg
│   └── index.js
├── webpack.config.js
└── package.json
```

Не забудьте, что в `dist/index.html` должен быть подключён `bundle.js`:

```html
<!DOCTYPE html>
<html lang="ru">
    <head>
        <meta charset="UTF-8">
        <meta name="viewport" content="width=device-width, initial-scale=1.0">
        <title>Webpack Test</title>
    </head>
    <body>
        <script src="bundle.js"></script>
    </body>
</html>
```

**Задание для самостоятельного выполнения**:

**1. Использование `asset/inline` для встраивания изображений**:

Тип `asset/inline` встраивает файл напрямую в JavaScript-бандл в виде Data URI. Это полезно для небольших изображений, чтобы уменьшить количество запросов к серверу.

**Задача**: Добавьте в проект маленькое изображение (иконку, менее 8 кб) и большое изображение (фотографию, более 8 кб). Используя тип `asset` с настройкой `dataUrlCondition`, убедитесь, что маленькое изображение встраивается как Data URI, а большое сохраняется как отдельный файл. Проверьте это в инструментах разработчика браузера во вкладке "Network" (Сеть).
